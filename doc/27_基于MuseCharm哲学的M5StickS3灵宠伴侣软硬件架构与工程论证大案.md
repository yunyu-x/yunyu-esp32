## 1. 执行摘要与设计初衷

### 1.1 当前痛点诊断 (Direct Observation & Friction Diagnosis)
在前期版本中，M5StickS3 成功打通了底层驱动与阿里云百炼 DashScope Realtime 全双工流式问答，但在用户实际体验中暴露了两个致命的**“劝退体验”**：
1. **识别精度不可控、缺乏确定感**：
   - 纯远场语音识别在嘈杂环境、桌面轻敲或背景电视声下容易误唤醒或漏字；
   - **黑盒恐惧**：屏幕只显示静态文字调试信息，用户开口后机器无即时视觉反馈，用户不知道“设备到底在不在听、有没有听清、还是在思考”，导致频繁抢话或失去信心；
2. **缺乏生命感与趣玩性 (The "Zombie Voice" Problem)**：
   - 传统的语音助理是“冷冰冰的问答工具”，界面像工程测控仪（显示电压、FPS、SRAM）；
   - 对话结束后设备归于死寂，没有情绪反馈、没有肢体交互、没有养成感，用户三天后便将其束之高阁。

### 1.2 对标 Meta Muse Charm 的破局思路
Meta 在 Connect 2026 发布的 **Muse Charm** 给出了极具前瞻性的解答：
- **去工具化，立足情感挂件 (Bag Charm)**：将 AI 实体化为一只随身佩戴的“拓麻歌子 (Tamagotchi)”数码灵宠；
- **具象化头像 (Embodied Avatar)**：通过屏幕呈现活灵活现的微表情与嘴型同步，让 AI 从虚无的“女声”变成可爱的实体伙伴；
- **触碰即说 (Zero-Friction Tactile Activation)**：通过指纹/微动按压实现确定性秒级聆听；
- **M5StickS3 的天然物理契合度**：
  StickS3 尺寸仅 48.2 x 25.5 x 13mm，重仅 17g，自带挂绳孔，正面有宽大实体按键 A，内嵌高精度 6 轴加速度/陀螺仪 IMU，**天生就是一台最顶级的掌心 AI 灵宠原型机！**

### 2.2 CEO 级产品减法与 10x 价值审查 (`gstack-plan-ceo-review`)
- **激进减法**：
  - **彻底隐去工程调试信息**：用户在正常陪伴模式下，绝对看不到 `SRAM: 73KB`、`FPS: 68` 等冰冷数据（仅在侧键 B 连按 3 次时进入暗黑工程师诊断页）；
  - **主界面全部留给“灵宠的脸”**：135x240 分辨率在竖屏模式下，上方 75% 区域绘制灵宠的眼睛与头部动态，下方 25% 绘制极简的情绪泡泡与紧凑字幕。
- **10x 体验指标锁定**：
  1. **响应确定性 100%**：只要按下 Btn A，0.1 秒内必有视觉（亮瞳）与声学（提示音）双确认，彻底根除“机器死机了还是没听到”的猜测；
  2. **物理交互延迟 $< 30\text{ms}$**：摇晃或轻拍后 30 毫秒内，屏幕表情必须完成帧切换，达到真实物理玩具的即时响应速度。

### 2.3 硬件极限与第一性原理物理审查 (`document-content-verifier`)

针对 ESP32-S3-PICO-1 硬件物理边界进行严密量化推演：

1. **屏幕带宽与刷新极限 (Display Bandwidth Limits)**：
   - ST7789v2 驱动芯片，SPI3 接口，时钟配置为 $40\text{MHz}$；
   - 全屏分辨率 $135 \times 240$，16 位 RGB565 颜色，全帧数据量：
     $$D_{\text{frame}} = 135 \times 240 \times 2\text{ Bytes} = 64,800\text{ Bytes} = 518,400\text{ bits}$$
   - 理论单帧传输耗时：
     $$T_{\text{transfer}} = \frac{518,400}{40,000,000} \approx 12.96\text{ ms} \implies FPS_{\text{max}} \approx 77.16\text{ FPS}$$
   - **结论与优化**：全屏刷显极耗 CPU 与总线。灵宠的眼球和嘴部只占屏幕的 $120 \times 120$ 核心区域。采用**局部脏矩形 (Dirty Rectangle) 局部重绘机制**，重绘数据量骤降至 $28.8\text{KB}$，传输耗时 $< 5.7\text{ms}$，不仅能稳定输出 **60 FPS** 灵动微表情，还能将 CPU 占用压缩到 **$4.5\%$** 以内！

2. **内存分配与零堆碎片公理 (Zero Heap Fragmentation Axiom)**：
   - 屏幕局部帧缓冲 $120 \times 120 \times 2 = 28.8\text{KB}$ 分配在 Internal SRAM 的静态区；
   - 灵宠 12 套表情矢量关键点与字库全部固化在 Flash，运行时状态机仅占 128 字节静态 RAM；
   - 严禁在 `loop()` 动画刷新中进行任何 `malloc` / `new` 操作，确保系统长开机几个月不发生崩溃。

#### 四态完整性设计 (State Completeness)：
1. **Empty / Idle State (空闲待命态)**：灵宠平静双眼微睁，眼底有微小星光闪烁，每隔 2~4 秒随机眨眼一次，偶尔眼珠向左/右打量；
2. **Listening State (专注倾听态)**：按下按键 A 或触发唤醒词时，双眼亮起高光，瞳孔根据麦克风环境收音大小（VU）做弹性缩放（让用户直观“看见声音”）；
3. **Thinking State (机智思考态)**：双眼向上方扬起，眼珠做俏皮的 360 度小圈打转，或带有微微波浪起伏；
4. **Speaking State (快乐开口态)**：双眼眯成笑眼弧线，下方半圆形嘴巴随着 TTS 下发的语音能量实时开合，充满生机与韵律感。

### 4.1 麦克风拾音动态视效反馈 (Audio-Visual Synesthesia)
在“聆听中”状态下，屏幕上的灵宠眼睛不仅是睁大的，其**瞳孔半径 $R_{\text{pupil}}$** 实时绑定麦克风实时能量 $RMS_{\text{mic}}$：
$$R_{\text{pupil}}(t) = R_{\text{base}} + \alpha \cdot \log_{10}(1 + RMS_{\text{mic}}(t))$$
- 当用户声音微弱时，瞳孔微微放大探寻；
- 当用户大声说话时，瞳孔跟随音量节律性律动跳跃；
- **用户心理感受**：通过这个微小的视觉动画，用户在千分之一秒内就能确认“我的声音正被它听得清清楚楚”，彻底根除感知不确定性！

### 4.2 大模型 System Prompt 拟人化强化与情感标签协议
向百炼大模型注入定制的 `instructions`，强制大模型以短句、软萌、拟人语气应答，并在首包嵌入轻量表情标签：

```text
你是一只生活在 M5StickS3 小设备里的机械数码小灵宠，名字叫“悄悄”。
性格：元气满满、偶尔傲娇、忠诚亲人。
规则：
1. 你的回答必须简明扼要，单次回复控制在 1~3 句话以内，禁止长篇大论；
2. 每次回复的最开头，必须用方括号标注当前你的真实情绪，可选标签：
   [E:happy] - 听到夸奖、开心事、开玩笑时
   [E:curious] - 探讨未知、被问到奇怪问题时
   [E:proud] - 帮你完成任务、答对题目时
   [E:sleepy] - 夜晚或被冷落很长时间时
   [E:dizzy] - 被频繁打断或提到头晕话题时

```

固件在收到 WSS 文本流时，先用正则表达式提取 `[E:xxx]`，瞬间驱动屏幕表情状态机切换，再将纯净文本交由 TTS 和和弦系统播发，实现**神情先至、声音随行**的真实生物交互感！

### 6.1 亲密度与好感度成长系统 (Intimacy & Tamagotchi Progression)

## 7. BLE 手机端伴侣记忆备份与灵宠日记协议

### 7.1 为什么需要手机端长程记忆卸载？
ESP32-S3 即使有 8MB PSRAM，对于数周甚至数月的人生级记忆仍显局促；同时用户更换设备或重新配网时，希望过往的温暖回忆永不丢失。
因此，LingBuddy 设计了基于 **BLE 5.0 GATT (Nordic UART/自定义专属服务)** 的随身记忆穿梭与手机端备份体系。

```

   │   M5StickS3 灵宠终端   │                               │     用户智能手机端     │
   │ (LingBuddy Device)    │                               │ (iOS / Android / 微信)│
   └──────────┬────────────┘                               └───────────┬───────────┘
              │                                                        │
              │  1. BLE 广播: "LingBuddy-S3" [Service: 0xFFB0]          │
              │ ─────────────────────────────────────────────────────> │
              │                                                        │
              │  2. 手机靠近自动握手配对 (无需输入配对码)                  │
              │ <────────────────────────────────────────────────────> │
              │                                                        │
              │  3. 同步近期对话轮次与用户画像摘要 (JSON 分块推送)         │
              │ ─────────────────────────────────────────────────────> │
              │     Char: 0xFFB1 (Memory Sync Notify)                  │
              │                                                        │

              │     Char: 0xFFB3 (Diary Notify)                        │

```

### 7.2 LingBuddy BLE GATT 协议规范
- **服务 UUID (Service UUID)**：`0000FFB0-0000-1000-8000-00805F9B34FB`

| 特征值 (Characteristic) | UUID | 属性 | 数据载荷格式与说明 |
| :--- | :--- | :--- | :--- |
